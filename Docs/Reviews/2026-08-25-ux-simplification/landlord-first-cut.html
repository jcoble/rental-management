Decide first

Two things that aren't simplification

The numbers disagree with each other

With the same sample data and date range, the web dashboard says Who's behind $5,175 · Kept this month $15,046 while the Money overview says $0.00 · $0.00 · Cash available $0.00, and the Money header strip says Past due $0.00 (0). Three surfaces, three answers. No amount of layout work survives a landlord deciding the app can't add. This is almost certainly a query-scoping bug and should be found and fixed before any of the items below.

A solo landlord can't reach listings on the web

Listings live only in the Leasing-role shell (/leasing/rentals), gated to experiences: ['Leasing'] (experience-policy.ts:74-80). A one-person portfolio — who is their own leasing agent — has no path to advertise a vacancy from the management shell. Product call needed: show the Leasing screens to a single-person workspace, or fold them into /applications.

Intrinsic complexity

What stays hard, on purpose

  • Screening, FCRA consent, adverse action. Federal law; reveal at the decision, not during listing work.
  • E-signature outside the landlord's app, and the immutable signed PDF. A landlord signing for a tenant voids the lease.
  • Security deposits as separately held, non-income money, including the deposits-exceed-cash warning — trust-accounting law in most states. Keep the rule; move the warning out of "Simple".
  • Double-entry accounting underneath. Keep the ledger, keep it off the daily screens. This is exactly "simple on the surface, full system underneath".
  • Depreciation, tax basis, 1099/W-9. Real Schedule E and IRS obligations. Off the create path, never deleted.
  • Payment allocation "oldest open charges first" shown as a preview, not a decision — the model the rest of the app should copy.
  • The typed GO LIVE confirmation before wiping sample data, and the all-or-nothing transactions behind move-in, move-out and deposits.
  • The capability system. Extend it (one owner + no team ⇒ hide the machinery); don't replace it with a "simple mode" toggle — the web already has one that hides nothing.
Incidental

Defects the reviewers tripped over

  • mobile/lib/features/leases/leases_list_screen.dart:311-315 — the empty-state button reads "Open applications" but calls onPrepareMoveIn.
  • mobile/lib/features/applications/application_detail_screen.dart:108-123 — _prepareMoveIn dereferences application.unitId! with no guard; an approved application with no unit crashes on tap.
  • mobile/lib/features/accounting/record_payment_sheet.dart:288 — the "document" control only changes a local label; it never selects or uploads a file.
  • Web dashboard briefing failed on first load with sample data ("took too long to load / Action items unavailable").
  • The web rail lists "Tenant notices" twice (Inbox and Settings), pointing at different pages.
