Mobile UI rescue audit

A read-only pass through 39 distinct route/state scenarios on the single Azure Android emulator found four release-blocking defects plus repeated navigation, wording, loading, density, and continuity problems. The app already has a useful Material 3 foundation; the rescue should repair shared systems and user language rather than repaint isolated screens.

Material 3 strengths to preserve

  • Five labeled primary destinations form a coherent bottom navigation model.
  • The platform date picker is readable, themed, and cancellable.
  • Inspection paging is explicit rather than silently truncating records.
  • Alert switches expose state and Applications has a clear share action.
  • Filled surfaces and typography already provide a workable visual foundation.

Implementation direction

  • Fix the shared FAB and content insets once, then prove every affected action.
  • Replace mystery horizontal scrolling with a visible section selector while keeping unit context persistent.
  • Translate wire enums and accounting terms at presentation boundaries.
  • Use contextual skeletons for initial loads and compact inline progress for pagination; do not freeze an otherwise usable page.
  • Block legal-notice approval when merge fields are unresolved or admin-only guidance remains.
  • Diagnose Deposits and Portfolio figures in SQL. All filtering, joins, grouping, aggregation, sorting, and paging must remain one translated DB-side query/view; no load-then-loop or N+1 repair is acceptable.
