Cross-cutting patterns

Fix these once at the root rather than 20 times at the call sites.

Date-wire discipline (local vs UTC)

Six findings trace to the same confusion. core/utils/date_wire.dart:23-29 already provides localToWireIso, but only the maintenance feature uses it. core/models/lease.dart:2 parses server date-only strings into local midnights, and core/time/app_clock.dart returns UTC normally but local on its 404 fallback — so every consumer is silently zone-dependent. Affects #4, #12, #18, #26, #28, #34.

PATCH bodies that omit emptied fields cannot clear anything

Building a request body with if (field.isNotEmpty) and sending it as a PATCH means an emptied field is read as "leave unchanged". The user sees a success message and the old value survives. work_order_detail_screen.dart already solves this correctly for unit and tenant with explicit clearUnit/clearTenant flags. Affects #9, #22.

Detail-screen mutations do not invalidate list providers

Four separate screens refresh only their own detail provider after a mutation, leaving the list behind them stale. In every case the delete path in the same file invalidates the list correctly, which marks these as omissions rather than deliberate choices. Affects #19, #20, #21, #23.

State written after an await with no guard

Riverpod notifiers assigning state after an await without ref.mounted, widgets calling setState or using ref after an await without mounted, and loaders with no request-generation counter so a stale response can clobber a newer one. activity_repository.dart and accounting_repository.dart already implement both guards correctly. Affects #16, #17, #24, #29, #37, #38, #39, #40, #41.

Idempotency applied inconsistently

IdempotentMutation.run retains a key across an ambiguous failure and clears it on success. Banking bypasses it entirely and mints a fresh UUID per attempt; the multi-notice send loop defeats it by retrying calls that already succeeded. Affects #2, #3, #7.

Failures swallowed with no user feedback

try/finally with no catch, or a bare await in a loader, so an API error escapes to the zone handler and the UI simply does nothing. The user reasonably concludes the action succeeded. Affects #25, #35.

Looked at hard and cleared

  • No client-side money aggregation anywhere. Every total, balance, NOI, trial-balance and running-balance figure is read from a server field — no fold/sum/groupBy over a fetched list, and no cents-vs-dollars unit mixups.
  • Role and capability gating fails closed. core/auth/mobile_access_policy.dart:156-310 defaults to false, every call site guards on an authenticated state first, and /access-denied is explicitly allowed so the deny redirect cannot loop. No portfolio-scoping or IDOR leak found.
  • Single-flight token refresh is correct. The completer is nulled before completion under an identical check and the mutation-replay guard fails closed on stale-revision recovery.
  • Scan confirm and upload idempotency are sound. A per-draft clientOperationId is retained across failures and the upload operation keys on payload hash plus context, so neither path can double-create.
  • Confidence scale is consistently 0.0–1.0 end to end — no 0–1 versus 0–100 mix-up.
  • Work-order transitions are server-driven via capabilities.allowedStatusTransitions, so no invalid-state action is offered from a hardcoded client enum.
  • Controller and timer disposal is near-universal across the reviewed lanes; the exceptions are listed above.
